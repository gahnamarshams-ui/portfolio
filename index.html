Projects · 01
Autonomous AI Agent · AI & Agentic AI
AgentX — Autonomous AI Agent for Intelligent Task Execution

AgentX takes a goal and carries it through to a checked result. A normal chatbot answers and stops. AgentX treats the request as a task: it plans the work, pauses when a step needs you, runs the approved step, and then checks whether that step succeeded.

Five agents, in plain words

  • Orchestrator Agent — Keeps the job in order and decides which agent should act next.
  • Planner Agent — Turns your goal into a short list of steps.
  • Safety Agent — Looks at a step and flags anything that should wait for your approval.
  • Executor Agent — Runs only the step that is allowed, using the tools the system can access.
  • Verifier Agent — Checks the result and says whether the step succeeded.

How one task moves

User Goal Planning Safety Check Human Approval Execution Verification Final Result

You describe the goal. The planner writes the steps, and anything sensitive waits until you approve it or cancel it. The executor then runs that step, and the verifier checks the result before the task is called complete.

Task states you will see

Pending Planning Awaiting Approval Running Completed Failed Cancelled

Pending is saved but not started. Planning is the step list being written. Awaiting Approval is paused for you. Running is an approved step in progress. Completed, Failed, and Cancelled are the three ways a task ends.

Technology stack

React.js Vite TypeScript Python FastAPI SQLite OpenAI API Git GitHub

React is the screen. FastAPI runs the agent flow. SQLite stores each task and its state. The OpenAI API is what the agents use to plan and check the work.

What I learned

How to split one AI job across agents, how a React screen talks to a FastAPI server, and why a check after execution matters as much as the plan.

How to explore AgentX

  1. Open the backend first and wait until it responds. The host sleeps when unused, so the first open can take a moment.
  2. Then open the frontend and try a goal.

Projects · 03
Python Application · Academic Performance Management
Student Grade Analyzer — Student Performance Management System

A menu-driven Python program for a class list. You add students, it calculates each result, and it can also summarise the whole class.

What you do in the menu

  • Add a student — Enter the name, a roll number, and marks for five subjects: English, Mathematics, Physics, Chemistry, and Computer Science.
  • The program checks the input — The name is validated, a roll number cannot be reused, and each mark must be between 0 and 100. Wrong input is caught with exception handling instead of crashing the menu.
  • See one report — Each record shows the five marks, the total out of 500, the average, a grade from A+ to E, and Pass or Fail.
  • Search — Find one student by roll number instead of reading the full list.
  • Read the class — The summary shows how many students were added, how many passed, how many failed, the class average, the pass percentage, and the class topper.

How a result is decided

Five marks are added out of 500, and the average sets a grade from A+ to E. A student passes only when every subject is at least 40. One subject below 40 means Fail, even if the average looks high.

Python used in the project

Functions Lists Dictionaries Loops Conditions Exception Handling Input Validation Modular Design

What I learned

Each menu action is its own function. The useful part was keeping records clean: reject a bad mark, refuse a duplicate roll number, and still give a clear report for one student and for the class.
